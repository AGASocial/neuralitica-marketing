## Spec Review — US-14.5

### Verdict: ALIGNED

Session-backed `getCurrentUser()`, deny-by-default route protection, every-request `neuramark_clients.active` (before `role` and before spend), SQL-only activation/promotion, no RBAC/activation UI, EN/ES, and `neuramark_` prefix match SPEC §2–§3 Authentication, SPEC §5–§6, AGENTS.md, PLAN Fase 1, and USER_STORIES US-14.5 / US-X.3. Logout **UI** stays US-14.3. Recovery leftover cookies are a SECURITY freeze, not a SPEC contradiction. No ADR, visual-modality, playbook/trend, or V1 out-of-scope breach.

### Terminology violations (CONTEXT)

None that block this story in `plan/stories/US-14.5/` (README.md, TASKS.md).

Canonical use: Cliente / Client, Operator (SQL activation and promotion), Usuario anónimo (auth pages only, no product until `active=true`). No playbook / trend / visual-modality copy in this story.

Do not ship _Evitar_ terms in product copy: **admin**, administrador, staff, prestador (as product role), usuario final. The TASKS phrase “admin lookup” is technical (service-role); keep it out of CONTRACT/SECURITY/UI strings.

Note (not a US-14.5 veto): parent `plan/USER_STORIES.md` Authentication blurb still says “admin activation UI”. Do not copy that into this story’s CONTRACT, SECURITY, or EN/ES strings.

### Recommended action

Proceed to **SECURITY.md** (security-architect), then CONTRACT.md.

CONTRACT freeze items (non-negotiable for alignment):

1. Single identity seam: `getCurrentUser()` session → `neuramark_clients`. Same `CurrentUser` shape. No second identity API. Cookie does not carry `active` / `role` / `client_id`.
2. Deny-by-default allowlist as in TASKS; `/pending` authenticated-inactive only; middleware not the security boundary; every product action/handler calls `getCurrentUser()` / `requireActive()` / `requireOperator()`.
3. `active` before `role` before any product or spend side effect. Inactive → pending (pages) / 403 (handlers). SQL activation/demotion visible on the next request.
4. `requireActive()` shipped now (no spend endpoints yet). `requireOperator()` shipped now (no operator product endpoints yet). Role never from header/cookie/body/middleware.
5. Dev fallback: dual flag, fixed-in-code user, production throw + test. Default path must not return the hardcoded user.
6. Cookie idle ≤ 7 days; httpOnly flags; service-role never on Edge / `NEXT_PUBLIC_*` / client.
7. No app write to `active` / `role` after the documented seed. RLS deny-by-default. `neuramark_` prefix.
8. EN/ES for new states; pending identity from server seam only.
9. Explicit out of scope: US-14.3 logout UI, Path A/recovery landing changes, RBAC/activation UI, Stories IG, Interview/Ficha/visual prefs.
10. **SECURITY (not SPEC):** freeze leftover recovery-session on product paths (normal session + `active` vs isolated). Do not veto the story on that choice unless SECURITY later contradicts SPEC (it currently does not).
