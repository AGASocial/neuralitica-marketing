## Spec Review — US-14.4

### Verdict: ALIGNED

Password recovery via Next.js (request + server-side token exchange + set-password), httpOnly recovery session, enumeration-safe generic responses, shared US-14.1 password policy, and **reset ≠ activation** match SPEC §2–§3 Authentication and AGENTS.md. Confirmation Path A stays frozen for signup/email; recovery must not share that landing or burn the token. `getCurrentUser()` stays hardcoded until US-14.5. No ADR, visual-modality, playbook/trend, or V1 out-of-scope breach.

### Terminology violations (CONTEXT)

None that block this story in `plan/stories/US-14.4/` (README.md, TASKS.md).

Canonical use: Cliente / Client, Operator (SQL activation), Usuario anónimo (reset without product access). No playbook / trend / visual-modality copy in this story.

Do not ship _Evitar_ terms in product copy: **admin**, administrador, staff, prestador (as product role), usuario final. Auth UX (“forgot password”, “reset password”) is not in CONTEXT; keep it as recovery/reset, not domain synonyms.

Note (not a US-14.4 veto): parent `plan/USER_STORIES.md` Authentication blurb still says “admin activation UI”. Do not copy that into this story’s CONTRACT, SECURITY, or EN/ES strings.

### Recommended action

Proceed to **SECURITY.md** (security-architect), then CONTRACT.md.

CONTRACT freeze items (non-negotiable for alignment):

1. Server Actions for request-reset and set-password; recovery token exchanged on a Next.js Route Handler — no `@supabase/supabase-js` / tokens / keys in the browser.
2. Dedicated recovery callback (preferred) **or** an explicit `type=recovery` branch that does **not** follow Path A. Path A signup/email landings stay frozen.
3. Token / `code` / `token_hash` never in client JS, logs, `Location`, HTML, or JSON. Set-password page + callback 302: `Referrer-Policy: no-referrer`.
4. One generic check-email success for known and unknown emails (same status, shape, copy); recovery call always runs when not rate-limited. Over-limit: same copy, 429. No timing oracle.
5. Shared `validatePassword` (US-14.1). CSRF on both mutations. Passwords never logged; `confirmPassword` off the wire. Forbidden keys (`role`, `active`, `auth_user_id`, `client_id`, …) rejected or stripped.
6. Rate limits on **request-reset only** via `neuramark_auth_attempts` / `password_reset_request` (3/email/hour and 10/IP/hour). No new tables. OTP ≤ 1 hour is ops/config.
7. Same observable flow for active, inactive, and unconfirmed. **Never** UPDATE `neuramark_clients.active` or `role`. Success → login (not dashboard/pending). Global sign-out then clear cookies.
8. Explicit out of scope: US-14.5 guards/spend/`getCurrentUser()` swap, US-14.3 logout UI, RBAC/activation UI, Stories IG, Path A changes for signup/email.
