Qué hay que construir realmente

La V1 no necesita una plataforma completa. Necesita una cadena mínima que permita capturar contexto del negocio, decidir el tipo de video, generar piezas, revisarlas, aprobarlas y aprender del resultado.

La lógica base del producto es: tomar información del negocio, convertirla en estrategia semanal y producir contenido listo para revisión y publicación.

Fases sugeridas

Orden recomendado de desarrollo

Fase 1

Base de entrada

  • Interview Builder
  • Business Profile
  • Avatar Mode Selector

Objetivo: tener la información mínima del negocio y el modo visual permitido.

Fase 2

Inteligencia de contenido

  • Content Strategy Agent
  • Video Script Agent
  • Caption Agent

Objetivo: transformar el contexto del negocio en piezas concretas de contenido.

Fase 3

Producción y control

  • Video Generator Connector
  • QA/Compliance Agent
  • Approval Flow

Objetivo: generar activos, validarlos y cerrar el ciclo con aprobación del cliente.

Fase 4

Operación semanal

  • Content Calendar

Objetivo: ordenar qué se entrega, cuándo se revisa y qué se publica manualmente.

Fase 5

Aprendizaje

  • Metrics Lite

Objetivo: capturar señales básicas para mejorar la siguiente semana sin construir analytics complejo.

Regla de producto

No meter de más en V1

  • No publicación automática obligatoria.
  • No automatización de DMs sensibles.
  • No TikTok, YouTube ni CRM avanzado.

Objetivo: mantener el alcance simple, vendible y validable.

Qué hace cada pieza

Interview Builder

P0 Input

Formulario o flujo guiado para capturar servicios, zona, tono, ofertas, objeciones, estilo y restricciones.

Salida: respuestas estructuradas del cliente.

Business Profile

P0 Core data

Ficha viva del negocio con la información consolidada que el resto de agentes reutiliza.

Salida: perfil canónico del cliente.

Avatar Mode Selector

P0 Rules

Define el modo visual permitido y aplica reglas de consentimiento y representación.

Salida: modo visual activo + restricciones.

Content Strategy Agent

P0 Planning

Genera pilares, temas, ángulos y secuencia semanal según el tipo de negocio.

Salida: brief semanal de contenido.

Video Script Agent

P0 Generation

Convierte la estrategia en guiones, hooks, CTA y texto en pantalla para cada Reel.

Salida: paquete de scripts por pieza.

Video Generator Connector

P0 Integration

Conecta con proveedor externo de video/avatar IA y devuelve el video generado o el estado del job.

Salida: assets de video.

Caption Agent

P0 Copy

Genera captions, hashtags, keywords y variantes de CTA alineadas con el Reel.

Salida: copy listo para revisión.

QA/Compliance Agent

P0 Validation

Revisa claims peligrosos, claridad, tono, uso correcto del avatar y consistencia con reglas V1.

Salida: aprobación interna o flags de corrección.

Approval Flow

P0 Delivery

Presenta contenido al cliente para aprobar, rechazar o pedir cambios antes de publicar.

Salida: estado de aprobación por pieza.

Content Calendar

P1 Ops

Ordena la semana: qué pieza va qué día, en qué estado está y qué falta aprobar o publicar.

Salida: calendario operativo semanal.

Metrics Lite

P1 Feedback

Guarda métricas simples para entender qué temas y formatos deben repetirse o ajustarse.

Salida: señales básicas para el siguiente ciclo.

Notas de infraestructura

OpenRouter y ClawRouter como piezas de soporte

Estas herramientas no reemplazan los módulos del producto. Funcionan como capa de acceso o ruteo para modelos, y podrían simplificar la implementación de los agentes de contenido si decidimos no acoplarnos a un solo proveedor.

Herramienta Qué aporta Dónde podría encajar Lectura para V1
OpenRouter Una API unificada para acceder a múltiples modelos y proveedores con compatibilidad tipo OpenAI. Content Strategy Agent, Video Script Agent, Caption Agent y QA/Compliance Agent. Puede acelerar la V1 porque evita integrar varios proveedores desde el día uno.
ClawRouter Router open source orientado a agentes, con ruteo local, selección automática de modelo y endpoint compatible con OpenAI. Capa de ruteo local por encima de los módulos generativos, especialmente si luego queremos optimizar costo y autonomía. Suena más útil como segunda fase técnica que como requisito inicial del MVP.
Nota 1

Qué nos dice OpenRouter

OpenRouter se presenta como una interfaz unificada para LLMs, con acceso a cientos de modelos sobre decenas de proveedores y compatibilidad con el SDK de OpenAI.

Para esta V1 eso sugiere una decisión pragmática: los módulos de generación de texto pueden programarse contra una sola interfaz mientras validamos producto, sin diseñar una abstracción compleja de proveedores desde el principio.

Implicación práctica: si usamos OpenRouter, el primer corte de Content Strategy Agent, Video Script Agent, Caption Agent y QA/Compliance Agent puede salir más rápido.

Nota 2

Qué nos dice ClawRouter

ClawRouter se posiciona como un router open source para agentes, con ruteo local, selección automática del modelo y compatibilidad con llamadas estilo OpenAI.

La señal importante no es solo el costo. La señal importante es arquitectónica: propone desacoplar la lógica de los agentes del proveedor final y mover la decisión de modelo a una capa de ruteo especializada.

Implicación práctica: si más adelante el sistema necesita optimizar calidad, costo o autonomía, ClawRouter podría volverse una buena base técnica para enrutar los módulos generativos sin reescribirlos.

Recomendación

Cómo lo aterrizaría en esta V1

  1. Construir los módulos P0 sin dependencia fuerte de un proveedor específico.
  2. Definir una interfaz interna simple tipo generateText(), reviewContent() y generateAssets().
  3. Usar OpenRouter si queremos velocidad de implementación al principio.
  4. Evaluar ClawRouter después, cuando exista volumen suficiente para justificar optimización de ruteo y costo.
Impacto por módulo

Módulos más afectados por esta decisión

  • Content Strategy Agent: depende del acceso confiable a modelos de texto.
  • Video Script Agent: probablemente será el consumidor principal de prompts y variantes.
  • Caption Agent: requiere costo bajo y rapidez, ideal para una capa de ruteo flexible.
  • QA/Compliance Agent: se beneficia de poder cambiar de modelo sin rehacer la lógica de revisión.
  • Video Generator Connector: queda separado, porque su integración principal seguirá siendo con proveedores de video/avatar, no con el router de texto.
